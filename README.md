# Powerball History Dashboard

澳洲 Powerball 历史开奖与统计分析静态网站，支持中文和英文。分析基于已收录结果，展示历史频率、遗漏和号码结构。

## 功能

- **统一范围**：最近 10、20、50、100、300 期、全部（`all`）或自定义日期（`custom`）；默认最近 100 期。日期区间包含起止日，预设期数不受保留的自定义日期影响。
- **历史与结构**：完整号码、区间着色、频率热力、连号、单期统计、PB 与主球重号；历史表按每页 50 期展示，可跳页。
- **号码分析**：主球与 PB 分别查看频率、遗漏和近 10/20/50 期趋势；支持按频率、遗漏或号码排序。
- **共现与图表**：主球全部 595 种号码对的共现次数及理论期望，默认展示前 30 对，可展开全部；图表包含比例、区间与和值变化，并提供对应基线说明。
- **可点击详情**：单期号码和结构指标；号码的范围频率、截止期遗漏、滚动 10 期曲线、最近 50 期命中轨迹、全部出现日期。日期和号码可以互相跳转查看。
- **关注与复用**：主球/PB 关注列表；最多 10 个命名分析方案；链接的 `#` 部分保留视图、范围、球池、排序、页码和语言。关注号码不会筛掉统计样本。
- **CSV 导出**：导出当前分析范围的完整记录或对应统计，不受当前页或共现“前 30 对”展示限制；带实际样本数、范围和截止期等元数据。

关注列表、分析方案及最近使用状态保存在当前浏览器的 `localStorage`，没有账户或跨设备同步。清除网站数据、更换浏览器、切换站点域名/端口会影响可用的本地记录；浏览器禁止存储时，当前会话仍可使用，但保存可能失败。分享链接不包含关注列表或已保存方案。

## 统计口径

**频率**为号码出现次数除以实际开奖期数。主球每期的理论出现率为 `7/35 = 20%`，PB 为 `1/20 = 5%`。近 10/20/50 期列均在所选范围内取样；不足相应期数时显示实际样本。趋势差值比较最近 10 期与再之前 10 期，使用百分点；没有前窗口样本时不显示差值。号码详情的滚动曲线只使用该期和之前最多 9 期，开头按实际样本数计算。

**遗漏**以所选截止期为准，向前检查全部可用历史，不被起始日期或最近 N 期窗口截断，也不使用截止期之后的开奖。截止期出现的号码遗漏为 0；历史中从未观察到的号码显示 `≥N`。最长完整遗漏只计算两次已知出现之间的间隔，不包含历史首尾未完成的间隔；没有完整间隔时显示 `—`。

**理论基线**考虑不同号码集合的大小：四个区间分别包含 10、10、10、5 个号码；主球奇偶为 18/17 个，小号/大号为 17/18 个。某一主球号码对在 N 期的期望共现次数为 `N × 7/35 × 6/34`。单期结构只统计 7 个主球，标准差采用总体标准差。

历史频率、冷热、遗漏和共现都描述已有样本，不改变公平独立开奖中下一期的理论概率。

## 数据来源与自动更新

数据来自 [Lotterywest 官方频率统计页面](https://www.lotterywest.wa.gov.au/results/frequency-charts)提供的 Powerball CSV 下载。`db.js` 保存规范化记录，格式为 `["DD/MM/YYYY", 主球1, …, 主球7, PB]`，球号为整数、主球升序、期数按日期降序；`data-status.json` 保存数据来源、最近尝试和最近成功同步状态。

只收录 **2018-04-19（第 1144 期）起**的现行规则：7 个 1–35 的主球及 1 个 1–20 的 PB。官方 CSV 中更早的旧规则结果不会混入分析。历史首端因此是规则与数据覆盖边界，不能据此推断此前的遗漏。此数据源提供开奖日期、期号和号码；本网站没有据此提供奖金、购买记录或个人投注收益。CSV 是官方网页的下载功能，没有承诺稳定的版本化开发接口。

更新时检查日期、期号、球号范围、重复号码/日期、缺期、未来日期和与已保存结果的冲突。异常时保留原有效开奖数据，并记录更新失败；不能把下载失败或过期结果当作新开奖。

GitHub Actions 工作流每天 **14:15 UTC** 尝试更新，也支持手动运行。新鲜度检查按 **Australia/Sydney 周五 12:00** 设置公布缓冲：此前允许再前一周四结果，从该时刻起要求最近周四结果；时区转换自动适配夏令时。定时任务的实际启动时间由 GitHub Actions 调度。

校验与测试通过后，工作流提交数据状态并构建、发布静态站点。更新失败时可发布保留的有效历史与失败状态，同时将报告任务标为失败；其他校验失败会阻止发布。来源限制、冲突处理和部署配置详见 [scripts/README.md](scripts/README.md)。

## 本地运行与验证

需要 **Node.js 22+**；以下预览命令还需要 **Python 3**。项目没有第三方运行依赖。

```sh
npm run serve
```

打开 `http://localhost:8765/`。页面使用 ES modules 并读取状态 JSON，需要通过 HTTP 服务访问；直接双击 `index.html` 的 `file://` 方式不能可靠加载这些资源。

```sh
npm test             # 运行离线自动测试
npm run validate     # 校验保存的开奖数据和状态一致性
npm run update-data  # 联网获取并校验官方结果，更新本地数据/状态
npm run build        # 将静态站点整理到 _site/，不上传或部署
```

`npm run build` 会重新生成 `_site/`。数据更新命令会写入 `db.js` 和 `data-status.json`；测试使用本地样本，不调用官方服务。

## 发布

添加工作流文件或运行本地构建不会自动启用线上更新；需要推送变更并启用下述发布配置。

准备发布时，将仓库 **Settings → Pages → Source** 设置为 **GitHub Actions**，允许工作流写入仓库内容，再将变更推送到当前工作流配置的 `master` 分支。完整步骤和工作流行为见 [更新与发布说明](scripts/README.md)。

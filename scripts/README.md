# Official result updates

Run `npm run update-data` with Node.js 22 or newer. It downloads the Powerball CSV that Lotterywest offers on [its frequency charts page](https://www.lotterywest.wa.gov.au/results/frequency-charts). The download address is `https://www.lotterywest.wa.gov.au/api/games/5132/results-csv`. The official site's frequency-charts component links `/api/games/{gameId}/results-csv`, and its game IDs module identifies Powerball as `5132`. This was verified against the site's actual client code and a successful CSV response on 2026-09-10. The download is a website feature, not a promised versioned developer API; a changed format fails validation.

The CSV includes earlier versions of the game. Only draws from 19 April 2018 (draw 1144), with seven main numbers from 1–35 and a Powerball from 1–20, enter this dashboard. Dates and main-number order are normalized before comparing against saved results. Official draw numbers must agree with weekly Thursday dates. All current-rule weeks must be present. Duplicate dates/numbers, future draws, invalid dates, empty responses, changed headers, stale source data and conflicting saved results stop the update. A conflict needs an evidence-based correction; the updater never overwrites it automatically.

The previous `db.js` is preserved when fetching, parsing, merging or writing fails. `data-status.json` records the failed attempt without changing its last successful synchronization. A successful no-change refresh is recorded as a successful verification only when the source is current enough. The website remains usable from saved data when the source is unavailable.

Freshness uses **Australia/Sydney local time**, including daylight saving. Results from a Thursday become required at **12:00 noon on the following Friday**. Before that deadline (including Thursday night and Friday morning), the previous Thursday is still allowed. For example, 3 September results are acceptable on Thursday 10 September 2026 and until 11:59:59 on Friday 11 September; at noon on Friday the source must include 10 September. A source that keeps returning the same old CSV after this deadline is an update error even if it matches the local data; neither the dataset nor `lastSuccessAt` advances.

`npm run validate` checks the saved dataset and status agreement. `npm test` includes CSV parsing, date/range validation, gaps, conflicts, repeated updates and preservation of saved data after failure. Tests use small fixtures and never access the network.

The workflow runs daily at **14:15 UTC** and can be run manually. It also validates pushes and pull requests. After an automatic/manual synchronization it validates, tests and commits only `db.js` and `data-status.json`. The same workflow uploads and deploys the current static artifact, so commits made using `GITHUB_TOKEN` do not need to trigger another workflow. Failed synchronizations publish the retained valid dataset with its failure status and mark a separate job failed for GitHub Actions notifications. Other validation failures stop publication.

Before the first hosted run, configure repository Settings → Pages → Source to **GitHub Actions**, and allow workflows to write repository contents. The workflow targets the repository's existing `master` branch. Creating these files locally does not activate Actions or deploy anything; they must first be pushed by the repository owner.

The Lott's actual result-details client exposes `latestresults` and `results/search/drawrange`, but the direct data request returned Access Denied during verification. This updater therefore uses Lotterywest's public CSV rather than relying on that unverified access path. No Lottolyzer fetching dependency is added.
